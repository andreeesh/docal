# Docal v0.4.0

Docal 0.4.0 adds local-only email capture for WordPress development with
Mailpit. Captured messages stay in a disposable local inbox; they are not
delivered to their addressed recipients.

## What's new

- **Shared Mailpit inbox:** `docal mail start`, `status`, `url` and `stop`
  manage a shared development inbox. Its web interface is published only on
  `127.0.0.1:8025`; SMTP is available to containers on `docal-proxy` at
  `docal-mailpit:1025` and is not published on the host.
- **PHP `mail()` capture:** newly generated WordPress images install
  `msmtp-mta` and route the PHP sendmail transport to local Mailpit.
- **WordPress `wp_mail()` capture:** existing sites can opt in with
  `docal mail enable <site>` and remove the Docal-managed integration with
  `docal mail disable <site>`. The reversible MU-plugin configures WordPress'
  PHPMailer to use local SMTP without authentication or TLS; it does not
  rewrite `wp-config.php`, rebuild the image or alter the database.
- **Operational checks:** `docal mail start` waits up to 15 seconds for the
  container, Docker network, loopback HTTP API and internal SMTP TCP port to
  work. `docal mail status` performs the same checks without waiting. A
  running container alone does not count as ready.
- **Safe Start isolation:** safe previews remain on their private internal
  network, do not join the Mailpit network and set PHP `sendmail_path` to
  `/bin/false`.

## Compatibility and limitations

- Existing WordPress images are not rebuilt or changed automatically. Older
  images without `msmtp-mta` may not route standalone PHP `mail()` to Mailpit;
  the opt-in WordPress MU-plugin uses PHPMailer directly for `wp_mail()`.
- Custom SMTP plugins, `pre_wp_mail` handlers and arbitrary PHP can bypass
  the capture hook or connect to external services. Mailpit is not an egress
  firewall or security boundary.
- The inbox UI has no authentication and must remain loopback-only. Treat
  captured messages as sensitive local data; use synthetic recipients and
  content for tests.
- Messages are temporary: Mailpit retains at most 500 messages for up to
  seven days and has no persistent volume. It is not a delivery service,
  backup or audit log.

## Validation

Mailpit lifecycle, network isolation, HTTP API, SMTP availability, PHP
`mail()` capture, existing-site MU-plugin behavior and Safe Start isolation
are covered by automated checks. WSL2/Docker Engine acceptance used synthetic
WordPress resources; no real recipients or SMTP credentials are required.
