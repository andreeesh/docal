# Docal v0.3.0

Docal 0.3.0 focuses on moving real WordPress installations into an
isolated, disposable local preview on Windows 11 + WSL2 with native Docker Engine.

## What's new

- **ZIP + SQL import:** `docal import <new-site> --zip site.zip --db database.sql.gz`
  restores a new local WordPress site without commercial migration plugins.
  Safe staging, guarded database loading, URL normalization and local
  administrator setup are included.
- **SSH pull:** `docal pull <new-site> --ssh <alias> --path <remote-wp-root>`
  retrieves WordPress content and database using a remote-read-only-designed
  WP-CLI/rsync workflow. `--dry-run` checks prerequisites before transfer.
- **Safe Start:** `docal start <site> --safe --port 8443` launches a preview
  with its own plugin-free WordPress file copy and disposable MySQL clone.
  The preview uses an internal Docker network, outbound IPv4/IPv6/DNS
  preflight checks and a loopback-only HTTPS endpoint.
- **Scoped cleanup:** `docal stop <site>` removes the temporary preview
  services, networks, files and private MySQL volumes while preserving the
  original local site's database and WordPress files.
- **Documentation and regression coverage:** updated import and security
  guides, safe-preview acceptance checklist and CI checks.

## Recommended workflow

```bash
docal import mysite --zip ./site.zip --db ./database.sql.gz
docal start mysite --safe --port 8443
# Inspect https://mysite.localhost:8443
docal stop mysite
```

If importing by SSH, replace the first command with:

```bash
docal pull mysite --ssh prod-alias --path /var/www/html
```

The source site's **local** MySQL container must already be running and
healthy before Safe Start. Safe Start refuses to start or reconcile it.

## Compatibility and limitations

- **WSL2/Docker Engine:** this remains a local-development tool, not
  production hosting or a hardened sandbox for arbitrary hostile PHP.
- **Normal start is different:** `docal start <site>` enables restored
  plugins on the normal Docal proxy; review integrations before using it.
- **Data handling:** SSH acquisition may collect private WordPress content
  and credentials stored in the database; obtain authorization and protect
  local copies. Remote WP-CLI startup hooks are outside Docal's control.
- **Consistency:** copying files and exporting SQL are not an atomic
  snapshot. The disposable database is a short-lived preview clone,
  not a durable backup.
- **Browser HTTPS trust:** local CA trust may differ across browsers and
  operating systems; a certificate can be valid yet not trusted locally.
- **Plugin behavior:** plugins/MU-plugins are omitted from Safe Start;
  plugin-dependent themes or pages may render incompletely.

## Validation

SSH/local restore and isolated Safe Start workflows were tested on WSL2
with Docker Engine. Safe Start's disposable MySQL behavior was verified
with synthetic WordPress data and checked that authenticated preview
writes do not affect the original local database. CI exercises syntax,
shell linting, mocked preflight/failure paths and documentation contracts.
